# Глоссарий

Единые термины для согласованной терминологии в документации и при изменениях кода.

- **PR (Pull Request)** — запрос на слияние в Gitea; в контексте сервиса — событие вебхука с полями `action`, `pull_request`, `repository`, `sender`. Поиск джобы Jenkins выполняется для действий `opened` и `reopened`. Проверки из `repositories[].checks` дополнительно выполняются для `synchronized`.

- **Webhook (вебхук)** — HTTP POST от Gitea на эндпоинт `/webhook` с телом в виде JSON события (тип в заголовке `X-Gitea-Event`). Подпись в заголовке `X-Gitea-Signature` (HMAC-SHA256, секрет из `server.webhook_secret`).

- **Job (джоба)** — задача в Jenkins. В API описывается полями `name`, `url`, `fullName`. Сервис ищет джобу по регулярному выражению в пределах `job_root`.

- **Правило репозитория (repository rule)** — элемент списка `repositories` в конфиге: привязка к репозиторию по полному имени (`name`), настройки поиска джобы (`job_root`, `job_pattern`, `poll_interval`, `timeout`) и шаблоны комментариев.

- **Проверка (check)** — элемент списка `checks` внутри правила репозитория. Поле может отсутствовать. Общие поля (`name`, `type`, `context`, `target_branches`, описания статуса) одинаковы для всех типов. Настройки типа лежат во вложенном объекте с ключом, равным `type`. Сейчас есть тип `file_blacklist`.

- **Целевая ветка** — ветка, в которую предлагается слияние (`pull_request.base.ref`). Правило проверки применяется, если эта ветка совпадает хотя бы с одним регулярным выражением из `target_branches`.

- **Чёрный список файлов (file blacklist)** — набор glob-шаблонов `file_blacklist.patterns`. Если pull request меняет хотя бы один подходящий путь, статус коммита — `failure`. Если таких путей нет — `success`. Учитываются `filename` и `previous_filename`.

- **Статус коммита (commit status)** — состояние проверки на SHA `pull_request.head.sha`, которое Gitea показывает на pull request. Публикуется вызовом `POST /repos/{owner}/{repo}/statuses/{sha}`. Разные проверки различаются полем `context`.

- **job_root** — «корневая» папка джоб в Jenkins (путь вида `folder/subfolder`). Пустая строка означает корень Jenkins. Используется в URL вида `/job/.../api/json?tree=jobs[name,url,fullName]`.

- **job_pattern** — строка, задающая регулярное выражение для имени джобы; может содержать Go-шаблон (например `{{ .Number }}`). Подставляются данные PR, затем строка компилируется в `regexp.Regexp`. Совпадение проверяется по полям `name` и `fullName` джобы.

- **Шаблон комментария (comment template)** — строка в формате Go `text/template`. Используются два шаблона: при найденной джобе (`success_comment_template`) и при отсутствии джобы (`failure_comment_template`). Доступные поля: `Number`, `Title`, `Repo`, `Sender`, `Timeout`; в успешном случае также `JobName`, `JobURL`.

- **poll_interval** — интервал между опросами Jenkins при ожидании появления джобы. Задаётся глобально в `jenkins.poll_interval` и при необходимости переопределяется в правиле репозитория.

- **timeout** — максимальное время ожидания появления джобы. Задаётся в `jenkins.timeout` и может переопределяться в правиле репозитория.

- **Очередь (queue)** — канал событий между HTTP-обработчиком и воркерами процессора. Размер задаётся `server.queue_size`. При переполнении вебхук получает 503.

- **Воркер (worker)** — горутина в процессоре, читающая события из очереди. Для каждого события выполняет подходящие проверки и публикует статусы коммита, затем при наличии правила репозитория опрашивает Jenkins и публикует комментарий.

- **Processor (процессор)** — компонент в `internal/processor`: очередь, пул воркеров, логика обработки одного события (фильтр репозитория/действия, шаблоны, вызовы Jenkins и Gitea).
