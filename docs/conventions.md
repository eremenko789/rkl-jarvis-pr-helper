# Конвенции

Именование, обработка ошибок, логирование и стиль кода для согласованности с проектом и при генерации кода.

## Именование

- **Файлы**: snake_case для имён файлов не принят; используются короткие имена в lowercase: `main.go`, `run.go`, `check.go`, `server.go`, `processor.go`, `config.go`, `client.go`, `types.go`.
- **Пакеты**: короткое имя в одном слове: `main`, `config`, `server`, `processor`, `jenkins`, `gitea`, `webhook`. Имя пакета совпадает с последней частью пути импорта (например `internal/config` → пакет `config`).
- **Символы**: экспортируемые типы и функции — PascalCase; неэкспортируемые — camelCase. Константы — PascalCase при экспорте (например `headerEvent`, `headerSignature` в server — неэкспортируемые). Параметры и локальные переменные — краткие осмысленные имена (camelCase).
- **Конфиг (YAML)**: ключи в snake_case (`listen_addr`, `webhook_secret`, `job_pattern`, `poll_interval` и т.д.).

## Обработка ошибок

- Функции возвращают ошибку последним возвращаемым значением: `(result, error)` или `error`. Ошибки создаются через `fmt.Errorf("context: %w", err)` для сохранения цепочки.
- В обработчиках HTTP при ошибке: логировать через `s.log.Error` (или аналог), вызвать `http.Error(w, message, code)` и выйти из обработчика. Не возвращать частичный ответ.
- В процессоре и клиентах: логировать ошибки и при необходимости прервать обработку события (без ответа клиенту — ответ уже 202). Контекст отмены (`ctx.Err()`) проверять и обрабатывать (например `errors.Is(err, context.DeadlineExceeded)`).
- В main/run: при ошибке загрузки конфига или запуска — вывести в лог и `os.Exit(1)`. В check — накапливать ошибки по этапам, в конце вывести сводку и выйти с кодом 0 или 1.

## Логирование

- Используется стандартный `log/slog`. Логгер передаётся в конструкторы (сервер, процессор, клиенты Jenkins/Gitea); если передан nil, используется `slog.Default()`.
- Уровни: `Debug` — детали запросов/ответов и внутренние шаги; `Info` — старт/остановка, принятые события, успешные действия; `Warn` — игнорируемые события, переполнение очереди, таймаут без джобы; `Error` — ошибки парсинга, API, постановки в очередь.
- Формат: в коде используется `slog.NewTextHandler(os.Stdout, ...)`. Поля передаются парами ключ-значение: `s.log.Info("message", "key", value)`.
- В команде run уровень задаётся флагом `-debug` (Debug иначе Info). В check при `-debug` тоже включается Debug.

## Стиль кода и форматирование

- Форматирование: **gofmt** (или goimports). В Makefile цель `make fmt` — `gofmt -w` по всем Go-файлам.
- Комментарии: для экспортируемых типов и функций — полное предложение, начинающееся с имени символа (например `// Load загружает конфигурацию...`). Пакетный комментарий описывает назначение пакета.
- Длина строки и отступы: стандартные для Go (tab для отступа, перенос длинных строк по вкусу с выравниванием).
- Импорты: группировка стандартная (stdlib, пустая строка, внешние пакеты, пустая строка, внутренние пакеты модуля). Сортировка по gofmt.

Следование этим конвенциям обеспечивает единообразие с существующим кодом и с целями `make lint` и `make fmt`.
