# Конфигурация

## Формат и расположение конфига

Конфигурация задаётся одним YAML-файлом. Путь передаётся флагом `-config` (например `config.yaml`). Пример файла в репозитории: [config.example.yaml](../config.example.yaml).

Загрузка и валидация: [internal/config/config.go](../internal/config/config.go) — функция `Load(path string) (*Config, error)` и метод `Validate()`.

## Секции и ключи

### server

| Ключ | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `listen_addr` | string | нет | Адрес прослушивания HTTP (по умолчанию `:8080`). |
| `webhook_secret` | string | да* | Секрет для проверки подписи вебхука (HMAC-SHA256). |
| `worker_pool_size` | int | нет | Размер пула воркеров (по умолчанию 4). |
| `queue_size` | int | нет | Размер очереди событий (по умолчанию 100). |

\* Если не задан, проверка подписи не выполняется (не рекомендуется для продакшена).

### jenkins

| Ключ | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `base_url` | string | да | Базовый URL Jenkins (например `https://jenkins.example.com`). |
| `username` | string | нет | Имя пользователя для Basic Auth. |
| `api_token` | string | нет | API-токен (пароль для Basic Auth). |
| `poll_interval` | time.Duration | нет | Интервал опроса джоб (по умолчанию 15s). |
| `timeout` | time.Duration | нет | Таймаут ожидания джобы (по умолчанию 5m). |
| `insecure_skip_verify` | bool | нет | Игнорировать ошибки SSL-сертификатов (по умолчанию false). |

Длительности задаются как строки с суффиксом: `15s`, `5m` и т.д.

### gitea

| Ключ | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `base_url` | string | да | Базовый URL API Gitea (например `https://gitea.example.com/api/v1`). |
| `token` | string | да | Персональный access token (заголовок `Authorization: token <token>`). |
| `insecure_skip_verify` | bool | нет | Игнорировать ошибки SSL (по умолчанию false). |

### repositories

Массив правил по репозиториям. Каждый элемент:

| Ключ | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `name` | string | да | Полное имя репозитория в формате `owner/repo`. |
| `job_root` | string | нет | Корневая «папка» джоб в Jenkins (путь вида `folder/subfolder`; пустая строка — корень). |
| `job_pattern` | string | да | Регулярное выражение для имени джобы; поддерживает Go-шаблон (например `{{ .Number }}`). |
| `poll_interval` | time.Duration | нет | Интервал опроса для этого репозитория (иначе из `jenkins.poll_interval`). |
| `timeout` | time.Duration | нет | Таймаут для этого репозитория (иначе из `jenkins.timeout`). |
| `success_comment_template` | string | нет | Шаблон комментария при найденной джобе (Go template). |
| `failure_comment_template` | string | нет | Шаблон комментария при отсутствии джобы (Go template). |
| `checks` | []object | нет | Проверки этого репозитория. Если поля нет, проверки для репозитория не выполняются. |

В шаблонах (включая `job_pattern`) доступны поля: `Number`, `Title`, `Repo`, `Sender`, `Timeout`; в шаблоне успеха дополнительно `JobName`, `JobURL`.

#### repositories[].checks

Правила проверки pull request конкретного репозитория. Каждое правило публикует отдельный статус коммита на SHA ветки head.

Общие поля одинаковы для всех типов проверок. Настройки конкретного типа лежат во вложенном объекте, ключ которого равен `type`. Чтобы добавить новый тип, достаточно нового значения `type` и своего вложенного объекта — см. [common-tasks.md](common-tasks.md).

| Ключ | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `name` | string | да | Имя правила, уникальное в пределах репозитория. |
| `type` | string | да | Тип проверки. Сейчас поддерживается `file_blacklist`. |
| `context` | string | нет | Контекст статуса коммита в Gitea (уникальный в пределах репозитория, не длиннее 255 байт). По умолчанию `checks/<name>`. |
| `target_branches` | []string | да | Регулярные выражения Go для целевой ветки PR (`pull_request.base.ref`). Правило применяется, если совпало хотя бы одно. Для всех веток укажите `.*`. Якоря `^` и `$` задают точное совпадение. |
| `success_description` | string | нет | Текст статуса при успехе. Для `file_blacklist` по умолчанию «Файлы из чёрного списка не изменены». |
| `failure_description` | string | нет | Текст статуса при неуспехе. Для `file_blacklist` по умолчанию «Изменены файлы из чёрного списка»; к нему дописываются совпавшие пути. |
| `file_blacklist` | object | да для этого типа | Настройки типа `file_blacklist`. |

`file_blacklist`:

| Ключ | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `patterns` | []string | да | Непустой чёрный список glob-шаблонов относительно корня репозитория. |

Синтаксис шаблонов путей:

- путь без спецсимволов совпадает только с этим файлом (`deploy/production.yaml`);
- `*` и `?` не переходят через `/` (`config/*.yaml`);
- сегмент `**` совпадает с любым числом каталогов, включая ноль (`**/.env`, `vendor/**`);
- сравнение чувствительно к регистру;
- путь должен быть относительным, без пустых сегментов.

Проверка выполняется только для репозитория, в чьём правиле она задана, и только для действий `opened`, `reopened` и `synchronized`. Успех — ни один изменённый путь (включая `previous_filename` при переименовании) не совпал с шаблоном. Неуспех (`failure`) — совпал хотя бы один. Если список файлов получить не удалось, публикуется статус `error`. Описание статуса обрезается до 255 байт.

## Значения по умолчанию и валидация

- **server**: `listen_addr` = `:8080`, `worker_pool_size` = 4, `queue_size` = 100, если не заданы или ≤ 0.
- **jenkins**: `poll_interval` = 15s, `timeout` = 5m при не заданных или ≤ 0. `base_url` обязателен.
- **gitea**: `base_url` и `token` обязательны.
- **repositories**: для каждого правила обязательны `name` и `job_pattern`. Если не заданы `poll_interval`/`timeout`, берутся из секции `jenkins`. Если не заданы шаблоны комментариев, подставляются строки по умолчанию (см. [internal/config/config.go](../internal/config/config.go), метод `Validate()`). Поле `checks` может отсутствовать.
- **repositories[].checks**: у каждого правила обязательны уникальные в пределах репозитория `name` и `context`, непустой `target_branches` из компилируемых регулярных выражений и настройки, соответствующие `type`. Одинаковые `name` и `context` в разных репозиториях допустимы. Чужой вложенный объект (например `file_blacklist` у другого типа) отклоняется. Для `file_blacklist` обязателен непустой `patterns`.

Валидация выполняется в `Config.Validate()` после разбора YAML; при ошибке `Load` возвращает ошибку.
